For the good of the country

Every state, county, city and ZIP code of the United States

A Rails engine holding the geography of the country as five tables your app joins to. Fifty states and the District. Three thousand one hundred and forty-four counties. Some thirty-two thousand Census places. Forty thousand nine hundred and seventy-seven ZIP codes.

Held once, and held right.

Raise it in three commands

In your Gemfile

gem 'usa', '~> 0.1.0'
  1. bin/rails g usa:installCopies the six migrations into your app, under timestamps of its own. There is nothing to configure.
  2. bin/rails db:migrateCreates the five tables and writes every row in them. Allow about a minute.
  3. bin/rails db:usa:seedFor a database made from a schema dump, which carries the tables and none of the rows. Every write is an upsert, so it is safe to run again.

The state of the union, before

Three copies of one country

Three applications each needed an address to mean something, so each grew a CSV of its own and a backfill to load it. Nobody loaded the same file twice, and nothing told any of them when the Census moved. The copies drifted, quietly, for years.

The first copy

Places off the 2010 list, still riding. 3,092 towns that were never added, and 8,893 the Census has since let go.

The second copy

Counties surveyed before Connecticut gave up its eight and drew nine planning regions, and before Alaska redrew six of its census areas.

The third copy

ZIP codes with nothing beside them — no city, no time zone — and 1,679 of the country’s missing outright.

The state of the union, after

One copy, maintained once

An app that adopts it stops carrying a CSV, a backfill and a table nobody owned. What it carries instead is a line in a Gemfile. The country is versioned, the changes are in a changelog, and every app that installs it is on the same vintage, because the same gem put it there.

A release that adds rows is bundle update usa and one seed. Every write is an upsert keyed on the code or the FIPS, so it inserts what is missing, updates what this gem owns, and leaves the id of every row you already had exactly where it was. Columns of your own, added in a migration of your own, survive every seed.

The manifest

Five tables, and what is in them

Every count below is what 0.1.0 writes, on the current Census vintage.

TableModelRowsWhat one row is
usa_statesUSA::State51 A state, or the District of Columbia: a code, a FIPS and a name.
usa_countiesUSA::County3,144 A county: a FIPS, a name and its state — Connecticut’s nine planning regions and Alaska’s current census areas included. Carries zips_count.
usa_citiesUSA::City32,058 A Census place off the 2025 Gazetteer: a place FIPS unique within its state rather than nationally, a name and a state.
usa_city_countiesUSA::CityCounty33,475 A city on a county it lies in: 1,291 places cross a county line and keep every one.
usa_zipsUSA::ZIP40,977 A ZIP code: the city it is addressed as, a time zone named as Rails names one, and one county.

All four records also carry a google_place_id, filled for every county and blank elsewhere until a release fills it. usa_states.counties_count and usa_counties.zips_count are counted from the rows after a seed rather than by a callback, since an upsert runs none.

In service

What you get

zip = USA::ZIP.find_by code: '90210'
zip.city         # => 'Beverly Hills'
zip.time_zone    # => 'Pacific Time (US & Canada)'
zip.county.fips  # => '06037'

county = zip.county
county.state.code # => 'CA'
county.zips_count # => 265
county.cities     # => [#<USA::City>, ...]

state = county.state
state.counties_count # => 58
state.cities         # => [#<USA::City>, ...]

Five tables and the associations between them, and nothing else: no pages, no controllers, no configuration.

# config/initializers/usa.rb
ActiveSupport.on_load :usa_zip do
  has_many :bookings, dependent: :destroy

  scope :served, -> { where.not markets_count: 0 }
end

Each model runs a load hook, so your app adds to it without reopening a file it does not own. The five are :usa_state, :usa_county, :usa_city, :usa_zip, and :usa_record, where you say how all of them connect.

Before you enlist

Two things worth knowing

The gem registers USA, ZIP and FIPS as acronyms before the engine loads, so a class of yours called Zip stops being found the day you install it. Rename it, or reach USA::ZIP instead.

An app that sets ActiveRecord::Base.table_name_prefix is not supported: the migrations name usa_states while the models would look for your prefix and the gem’s together.
